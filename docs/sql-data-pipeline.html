SQL query or data pipeline problem

Use this when a query returns wrong results, runs slowly, or a data pipeline breaks.

Steps

  1. Reproduce the problem on a small, known data sample.
  2. For wrong results: check joins (duplicates from one-to-many), NULL handling and filters.
  3. For slow queries: read the query plan (EXPLAIN) and look for full table scans and missing indexes.
  4. For broken pipelines: find the first failing step in the logs and check whether the source data changed.
  5. Fix, then add a test or data-quality check so it does not happen again.
  6. Write down what broke and why in the team channel.

Common pitfalls

  • Fixing the symptom downstream instead of the source.
  • Testing only on the full data set, which hides the cause.
